# Changelog

## 1.2.0

### Исправлено

- `Base.partial()` больше не мутирует исходную модель. Раньше метод присваивал
  `default = None` объектам `FieldInfo` самой модели, из-за чего все её поля
  становились необязательными; порча проявлялась отложенно — при любом
  `model_rebuild()` и во всех схемах, произведённых от модели после вызова
  `partial()`.
- `partial()` делает аннотацию `Optional[...]`, поэтому partial-схема принимает
  явный `null`, а не только отсутствие ключа.
- `only()` / `exclude()` тоже строят поля из копий `FieldInfo` — производная схема
  не разделяет изменяемое состояние с исходной моделью.

### Breaking changes

- `partial()` строится на `Base`, а не на исходной модели (как `only()`/`exclude()`).
  `issubclass(Model.partial(), Model)` было `True`, стало `False`; partial табличной
  модели — обычный DTO без таблицы (раньше наследовал `__table__` и выдавал
  `UserWarning` про затенение полей). `model_config` и валидаторы исходной модели
  в partial-схему больше не переносятся.
- `only()` бросает `ValueError` на имена полей, которых нет в модели (раньше
  опечатка молча давала схему без этого поля). `exclude()` по-прежнему игнорирует
  неизвестные имена — так один набор исключений переиспользуется для моделей
  с разным составом колонок.
